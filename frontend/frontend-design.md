## 1. 文档结论

经过产品定位、目标用户、演示目的、页面结构、核心流程、视觉方向、隐私表达、眼镜界面和商业叙事等多轮讨论，目前已经具备进入信息架构、线框和视觉设计的完整条件。

以下事项已经明确：

- 网站首先是一个可点击操作的真实消费产品原型，而不是营销官网或内部控制台；
- Web 是 Reality 面向用户的完整产品，RV101 是现实情境中的极简延伸；
- 网站同时承担活动演示和投资人产品证明，但始终保持消费者产品调性；
- 首位用户是独居、容易丢三落四、相信未来科技但务实严谨的在职用户；
- 英雄场景是寻找从工作桌掉到桌下的充电器；
- 核心信任不是“记录得更多”，而是“只保存结构化位置和变化，并且可以随时暂停”；
- “真实世界 Git”是面向团队和投资人的概念隐喻，产品界面不使用 Git、提交、分支等工程词汇；
- 主品牌使用 `Reality`，中文名为“在场”；
- Web 采用响应式设计，支持笔记本浏览器和手机竖屏浏览器；
- 眼镜使用全屏第一视角模拟，不画设备外框；
- 整体视觉为安静可信、高端克制的“Quiet Reality / 安静现实”。

尚未固定的内容仅限视觉稿阶段可验证项，例如最终色值微调、具体字标字形、首屏询问入口的视觉权重和第一视角素材选择。这些事项不影响页面结构和设计启动。

## 2. 产品定义

### 2.1 一句话定位

Reality 是一个帮助用户记住现实状态变化、找回物品位置，并由用户掌控记忆边界的个人现实记忆产品。

### 2.2 面向投资人的概念

> 真实世界 Git：现实状态可以形成版本、查看变化、回到过去、纠正错误，但普通用户不需要理解版本控制。

### 2.3 面向用户的核心表达

> 记住变化，不保存生活录像。

### 2.4 用户看完后应该相信什么

网站最重要的信任结论是：

> Reality 不是持续监控系统。它只保留结构化的位置和变化，记录可以随时暂停。

### 2.5 用户价值

用户不需要主动维护物品清单。Reality 通过有限、受控的观察形成现实记忆，并帮助用户回答：

- 我的充电器在哪里？
- 它之前放在哪里？
- 什么时候发生了变化？
- 系统为什么这样判断？
- 我能否暂停、纠正或忘记这条记忆？

## 3. 目标用户

### 3.1 首位用户画像

| 维度 | 描述 |
|---|---|
| 生活状态 | 独居，有稳定工作 |
| 主要问题 | 容易忘记常用物品放在哪里 |
| 科技态度 | 相信未来，愿意尝试智能硬件和智能家居 |
| 决策风格 | 务实、严谨，不接受虚假的 AI 承诺 |
| 关注重点 | 实际效果、隐私边界、可靠性和解释能力 |
| 付费动机 | 减少找物时间，降低生活中的记忆负担 |

### 3.2 网站主要观众

活动评委，同时也是潜在投资人。

评委应当通过五分钟以内的现场操作理解：

1. 产品解决的是高频、真实的生活问题；
2. Reality 与普通摄像记录、家庭监控或物品管理软件不同；
3. Web、眼镜和记忆平台构成了可扩展的完整产品；
4. 产品可以通过订阅和多设备扩展形成长期商业价值。

### 3.3 不采用的用户关系

首版不强调“家庭陪伴”或拟人化 AI。产品与用户的关系应当像可靠的生活基础设施，而不是情感伙伴。

## 4. 产品目标与非目标

### 4.1 当前目标

- 提供一个像真实产品一样可操作的响应式 Web App；
- 证明物品位置变化能够被查看和回拨；
- 证明现实查询可以自然延伸到 RV101 眼前；
- 证明用户可以一键暂停记录；
- 在不破坏消费产品调性的前提下，暗示订阅与多硬件商业价值；
- 让评委在五分钟内自由探索产品，同时自然发现英雄流程。

### 4.2 当前非目标

- 不制作营销型落地页或大段功能介绍；
- 不制作内部开发者控制台；
- 不制作全屋精确 3D 数字孪生；
- 不把 Web 做成照片、视频或生活录像浏览器；
- 不在首页暴露数据库字段、模型参数和精确置信度；
- 不在产品界面使用 Git、提交、分支、投影等工程语言；
- 不在 Glass 上展示完整导航、时间线、审计或长列表；
- 不展示具体订阅价格；
- 不强调 AI 陪伴、情绪价值或家庭温情。

## 5. 品牌与语言

### 5.1 品牌层级

| 层级 | 名称 | 用途 |
|---|---|---|
| 消费产品主品牌 | Reality | 产品界面、字标、设备和订阅 |
| 中文名 | 在场 | 中文品牌辅助表达 |
| 项目概念 | 真实世界 Git | 活动讲解、投资人理解、团队内部表达 |
| 核心空间 | 我的家 | 产品首屏与家庭现实域 |

建议品牌组合：

```text
Reality
在场
```

首版可以使用纯文字字标，不强制设计独立图形 Logo。

### 5.2 品牌气质

优先级最高：

- 安静可信；
- 高端克制；
- 精密可靠；
- 面向未来但不过度科幻。

明确避免：

- 家庭陪伴感；
- 可爱拟人；
- 情绪化 AI；
- 监控系统感；
- 开发者工具感；
- 霓虹科幻演示感。

### 5.3 产品文案原则

Web 使用客观事实表达：

> 充电器最近一次在工作桌下方被看到。

事件推断保留边界：

> 充电器可能从桌上掉到了下面。

眼镜回答可以更自然、直接：

> 找到了，你的充电器掉在工作桌下面了。

禁止使用：

- “我一直在看着你的家”；
- “我完全理解你的生活”；
- “我永远不会忘记”；
- 拟人表情、颜文字和陪伴式安慰；
- 将低可信判断包装成确定事实。

## 6. 信息架构

### 6.1 一级导航

一级导航保持三个入口：

1. **现在**：Reality 当前保存的家庭状态与最近变化；
2. **回拨**：按对象、空间和时间查看过去状态；
3. **问问**：通过文字或模拟语音查询现实记忆。

桌面端使用左侧导航；手机端使用底部导航。

### 6.2 次级入口

右上角头像菜单包含：

- 记忆；
- 设备；
- 隐私；
- 开放能力。

手机端不增加第四个“更多”底部标签，次级功能仍由右上角头像进入。

### 6.3 非导航页面

- 对象详情；
- 对象回拨；
- 纠正位置；
- 忘记记忆；
- Glass 第一视角模拟；
- 卫生间禁采模拟；
- 暂停后的系统状态。

### 6.4 页面树

```text
Reality
├─ 现在
│  ├─ 我的家
│  ├─ 对象详情
│  ├─ 最近变化
│  └─ 问询入口
├─ 回拨
│  ├─ 范围选择
│  ├─ 时间轨道
│  ├─ 事件步进
│  └─ 回到现在
├─ 问问
│  ├─ 查询输入
│  ├─ 模拟语音
│  ├─ 查询结果
│  └─ 戴上眼镜查看
└─ 头像菜单
   ├─ 记忆
   ├─ 设备
   ├─ 隐私
   └─ 开放能力
```

## 7. 演示家庭与数据设定

### 7.1 家庭空间

首版家庭包含：

- 客厅；
- 卧室；
- 玄关；
- 卫生间。

卫生间是禁采区域。

### 7.2 客厅结构

```text
客厅
├─ 工作区
│  ├─ 工作桌
│  ├─ 充电器
│  └─ 《设计中的设计》
├─ 沙发区
│  └─ 遥控器
└─ 通往玄关
   └─ 钥匙托盘
```

卧室和卫生间默认以较低信息密度显示。卫生间在地图上可以带克制的隐私状态，但“当前空间已禁采”的强反馈主要出现在 Glass 可选场景中。

### 7.3 首页背景记忆

| 对象/内容 | 当前记忆 | 用途 |
|---|---|---|
| 充电器 | 工作桌下方 | 英雄对象 |
| 钥匙 | 玄关托盘 | 找物能力背景 |
| 遥控器 | 客厅沙发 | 空间记忆背景 |
| 《设计中的设计》 | 读到第 86 页 | 生活进度 |
| 快递 | 明天下午领取 | 任务记忆 |

这些背景内容用于表达 Reality 已经运行一段时间，但首页不展示“已理解 12 天”等 AI 化描述。

“记忆从何时开始”只出现在隐私页面。

## 8. 首页设计

### 8.1 首页目标

用户在不阅读说明的情况下，应当在数秒内理解：

- 这是“我的家”的当前状态；
- Reality 正在记录或已经暂停；
- 客厅中有一个值得注意的位置变化；
- 用户可以直接询问物品位置。

### 8.2 首屏信息顺序

1. 品牌、`我的家`与记录状态；
2. 家庭语义地图；
3. 充电器变化提示；
4. 完整询问输入栏；
5. 少量最近记忆。

### 8.3 地图构图

地图采用“二维平面图 + 抽象语义区域”的混合方式：

- 看得出客厅、卧室、玄关和卫生间的关系；
- 客厅是视觉中心；
- 不表现精确尺寸、坐标和建筑图纸细节；
- 不使用 3D；
- 不使用自由知识图谱；
- 默认只展示稳定对象、重要变化和隐私状态；
- 小物品按空间聚合，避免对象散点过多。

### 8.4 对象表现

- 英雄对象充电器使用小型真实感切图与名称；
- 钥匙、遥控器和书籍使用克制图标或简化切图；
- 次要状态主要使用图标与文字；
- 地图不应像游戏背包、资产清单或家庭监控面板。

### 8.5 询问入口

首页地图下方显示完整输入栏：

```text
[ 我的充电器在哪里？                              麦克风 ]
```

进入对象详情或回拨页面后，询问入口缩为底部命令栏：

```text
[ 问问 Reality                                    麦克风 ]
```

首页询问入口需要明显，但不能压过家庭地图。视觉稿阶段可微调地图与输入栏的相对权重。

### 8.6 自发现设计

不使用传统新手教程或三步浮层。

通过以下方式让页面自己说话：

- 充电器位置变化出现一次轻量脉冲；
- 附带一句短提示；
- 可点击对象具有明确但克制的悬停和触摸反馈；
- 主动作遵循自然阅读顺序；
- 不循环闪烁，不持续抢占注意力。

## 9. 英雄对象与事件故事

### 9.1 英雄对象

充电器。不区分充电头、线缆和整套充电器，不增加对象识别复杂度。

### 9.2 故事

充电器从工作桌上掉到地面，用户最终在工作桌下面找到它。

### 9.3 事件时间线

```text
08:42  在工作桌上被看到
10:16  可能从桌面掉落
10:18  在工作桌下方再次被看到
现在   最佳位置仍是工作桌下方
```

### 9.4 分层措辞

首页事件：

> 充电器可能从桌上掉到了下面。

详情中的依据：

> 10:16 前仍在桌面，10:18 在工作桌下方再次被看到。

Web 查询结果：

> 充电器最近一次在工作桌下方被看到。

Glass 回答：

> 找到了，你的充电器掉在工作桌下面了。

产品通过这一组措辞同时保持故事性、自然感和证据边界。

## 10. 对象详情

### 10.1 页面目标

对象详情负责回答四个问题：

1. 它现在最可能在哪里？
2. 最近发生了什么变化？
3. Reality 为什么这样判断？
4. 用户如何纠正或忘记？

### 10.2 页面模块

- 对象名称与简化形象；
- 当前最佳位置；
- 最近观察时间；
- 新鲜度；
- 简化移动路径；
- “为什么这样判断”；
- 查看完整回拨；
- “不是这里”纠正；
- 忘记这条记忆。

### 10.3 可信度表达

首页不显示置信度百分数。默认通过视觉语法表达：

| 视觉 | 含义 |
|---|---|
| 实线 | 高可信或已确认状态 |
| 虚线 | 系统推断 |
| 半透明 | 仍在候选期 |
| 分叉 | 存在冲突版本 |
| 褪色 | 信息已经陈旧 |
| 用户标记 | 用户确认或纠正 |
| 空白删除标记 | 内容已删除，仅保留最小回执 |

进入详情后才使用人类语言解释：

> 两次观察一致，尚未由你确认。

## 11. 回拨体验

### 11.1 交互原则

采用连续时间轴与事件步进结合的方式：

- 用户拖动时间轴到大致时间；
- 使用前后事件按钮精确切换；
- 地图根据所选时间更新；
- 页面保留低存在感的“回到现在”。

### 11.2 桌面布局

```text
上方/中央：客厅语义地图
下方：连续时间轨道
右侧：当前时间点与变化说明
```

### 11.3 手机布局

```text
上方：地图
中间：当前事件说明
底部：时间轴、前后事件按钮
辅助位置：低存在感的“回到现在”
```

### 11.4 状态变化

- 拖到 10:15，充电器回到工作桌；
- 切换到 10:16，显示可能掉落事件；
- 切换到 10:18，充电器移动到桌下；
- 点击“回到现在”，恢复当前最佳状态。

### 11.5 动效

- 时间拖动不逐帧模拟完整世界；
- 对象在关键事件之间平滑过渡；
- 路径短暂生长，用来解释移动；
- 过渡约 500ms，保持可理解但不拖慢操作。

## 12. 问问 Reality

### 12.1 产品形态

“问问”不是聊天消息流，而是临时现实查询界面。

### 12.2 页面模块

```text
你想知道什么？
[ 我的充电器在哪里？                              麦克风 ]

最近询问
- 充电器在哪里
- 钥匙最后一次出现在哪里
- 我读到第几页了
```

### 12.3 输入方式

- 文字输入；
- 麦克风按钮；
- 模拟语音输入；
- 可使用预设问题保证活动演示稳定。

### 12.4 查询结果

查询结果应包含：

- 对象名称；
- 当前最佳位置；
- 观察时间；
- 新鲜度；
- 必要时的备选位置；
- 查看对象详情；
- `戴上眼镜查看`主要动作。

不显示内部 ID、模型字段或原始数据库结构。

## 13. Glass 第一视角模拟

### 13.1 定位

Glass 是 Web 产品在现实场景中的最小必要延伸，不是另一个完整应用。

### 13.2 进入方式

用户从查询结果点击：

```text
[ 戴上眼镜查看 ]
```

浏览器进入全屏第一视角模式。

### 13.3 视觉形式

- 不画眼镜设备外框；
- 使用轻微虚化的工作桌第一视角照片；
- 页面边缘保留非常轻的镜片暗角；
- HUD 使用单绿色；
- 一屏只显示一个结论；
- 不展示相机预览框、长列表或完整页面；
- 不制造虚假的空间锚定。

### 13.4 找物回答

```text
我的充电器在哪里？

             ↓

找到了
你的充电器掉在工作桌下面了
10:18 看到
```

向下箭头只表达语义方向，不暗示设备具备精确空间追踪。

普通答案在 3-5 秒后淡出。

### 13.5 禁采场景

Glass 模式提供可选第二场景：进入卫生间。

```text
当前空间已禁采
```

该状态使用固定安全图形或实线框，优先级高于普通提醒。

### 13.6 暂停状态

```text
现实记录已暂停
```

眼镜模拟全程只使用字幕，不播放系统语音。

## 14. 隐私与暂停

### 14.1 核心承诺

- 只保存结构化位置和变化；
- 不提供连续生活录像；
- 用户可以随时暂停；
- 原始证据删除后不伪造媒体回看；
- 记忆形成时间和记录范围可查看。

### 14.2 全局状态入口

顶部常驻状态示例：

```text
Reality 正在记录
```

点击展开：

```text
暂停现实记录
忘记最近 10 分钟
查看记录范围
```

### 14.3 暂停行为

暂停一键立即生效，不需要二次确认。

暂停后：

- 顶部状态变为“已暂停”；
- 房间地图停止产生新变化；
- Glass 显示“现实记录已暂停”；
- 演示停在暂停状态，不继续恢复流程。

### 14.4 删除与忘记

删除不能伪装成瞬时完成。界面需要区分：

- 请求已提交；
- 本地证据已清除；
- 云端记忆和索引清理中；
- 删除完成；
- 部分失败并继续重试。

### 14.5 隐私页面

隐私页面包含：

- 当前记录状态；
- 记忆开始时间；
- 禁采空间；
- 原始证据留存规则；
- 最近暂停和删除记录；
- 忘记最近一段时间；
- 单条记忆删除入口。

- 默认按最近变化组织，不按数据库类型组织；
- 支持按对象、任务、偏好和进度筛选；
- 不将其设计成传统待办 App 或笔记 App；
- 点击任一记忆可进入来源、时间和纠正视图。

## 18. 视觉设计系统

### 18.1 视觉主题

> Quiet Reality / 安静现实

整体感觉是安静可信、高端克制、精密可靠。它应当像成熟的消费电子产品，而不是家庭监控系统、资产管理后台或科幻概念片。

### 18.2 建议色彩角色

| 角色 | 建议方向 | 用途 |
|---|---|---|
| 主背景 | 冷白、浅灰 | 页面和地图底色 |
| 主要文字 | 墨黑、深炭灰 | 标题、正文、空间名称 |
| 品牌/确认 | 深青绿 | 运行、确认、品牌强调 |
| 变化 | 信号橙、克制琥珀 | 事件、时间节点、变化脉冲 |
| 安全错误 | 低饱和红 | 错误、不可逆删除 |
| Glass HUD | 单绿色 | 第一视角字幕和状态 |

不使用大面积米黄、紫色渐变、蓝紫霓虹或单一深蓝色主题。

最终色值在视觉稿阶段根据对比度和投影设备表现确定。

### 18.3 字体

- 界面、地图和正文使用现代无衬线字体；
- 标题保持紧凑但不使用负字距；
- 时间数字使用等宽数字特性；
- 不使用手写体；
- 不使用衬线字体制造回忆录感；
- 中英文混排需要统一视觉高度和字重。

### 18.4 形状与容器

- 页面区域优先使用无框布局和分隔线；
- 不将所有内容包装成浮动卡片；
- 不在卡片内继续嵌套卡片；
- 单项记忆、弹窗和工具面板可以使用卡片；
- 圆角不超过 8px；
- 图标按钮使用熟悉符号并提供悬停说明；
- 状态不能只依赖颜色表达。

### 18.5 不确定性视觉语法

- 实线：高可信或已确认；
- 虚线：系统推断；
- 半透明：候选；
- 分叉：冲突；
- 褪色：陈旧；
- 用户标记：确认或纠正；
- 空白删除节点：已删除，仅保留回执。

---

## 19. 动效与声音

### 19.1 动效原则

动效负责解释状态变化，不负责制造科技氛围。

### 19.2 建议速度

- 普通操作：200-300ms；
- 地图回拨：约 500ms；
- 进入 Glass 模式：可以使用更慢的一次沉浸过渡；
- Glass 普通内容：3-5 秒后淡出。

### 19.3 关键动效

- 充电器变化出现一次低调脉冲；
- 移动事件使用短促路径生长；
- 回拨时对象平滑返回旧位置；
- 暂停后地图停止事件动画；
- Glass 模式使用黑场或轻微暗角淡入。

### 19.4 声音

- 普通 Web 操作不播放声音；
- 关键模式进入和确认可以使用短促提示音；
- 现场环境允许声音；
- Glass 模拟全程只显示字幕，不播放回答语音。

---

## 20. 图片与媒体策略

### 20.1 使用位置

- 首页不使用大幅真实房间照片；
- 语义地图是首页主视觉；
- 充电器可以使用真实感物品切图；
- 对象详情可以使用小型场景示意；
- Glass 模式使用全屏第一视角工作桌照片；
- 可生成独居住所、工作桌和物品素材。

### 20.2 媒体边界

- 照片只负责建立场景感和第一视角沉浸；
- 不让用户误以为系统长期保存了原始照片；
- 原始证据已删除后不显示照片缩略图；
- 可以显示隐私友好的语义草图、图标和相对位置；
- 不制作照片墙、媒体时间线或生活相册；
- 当前演示不依赖视频。

## 21. 响应式设计

### 21.1 目标环境

- 笔记本电脑浏览器；
- 手机浏览器；
- 手机只保证竖屏；
- 不要求手机横屏体验。

建议重点验证：

- 1440 x 900；
- 1280 x 800；
- 390 x 844；
- 360 x 800。

### 21.2 桌面结构

- 左侧一级导航；
- 中央现实画布；
- 右侧对象或事件上下文；
- 底部时间轨道；
- 右上角头像进入次级功能。

### 21.3 手机结构

- 顶部品牌、家庭名称和头像；
- 主内容单栏；
- 对象详情使用底部面板或独立页面；
- 一级导航固定在底部；
- 回拨页面采用地图、事件说明、时间控制纵向排列；
- 询问输入不能被虚拟键盘遮挡；
- 固定控件需要明确高度，避免动态内容导致跳动。

### 21.4 响应式原则

桌面不是简单放大手机卡片，手机也不是裁切桌面画布。两端共享信息架构，但使用适合各自空间的组合方式。

## 22. 页面状态

每个核心页面需要覆盖以下状态：

- 正常；
- 加载；
- 无记忆；
- 仍在学习；
- 信息陈旧；
- 存在冲突；
- 已暂停；
- 当前空间禁采；
- 设备离线；
- 查询无结果；
- 删除进行中；
- 删除完成；
- 删除部分失败；
- Glass 模式退出。

“未知”是正式产品状态，不能统一显示为空页面或系统错误。

---

## 23. 可用性与无障碍

- 所有关键状态同时使用图形、文字或线型，不只使用颜色；
- 正文、按钮和状态达到合理对比度；
- 支持键盘完成核心演示流程；
- 触摸目标适合手机操作；
- 动效尊重减少动态效果设置；
- 第一视角暗角不能降低字幕可读性；
- Glass 字幕行数和长度保持稳定；
- 中文长文本不能溢出按钮或面板；
- 时间轴在触摸设备上提供事件步进按钮，不能只依赖精细拖动。

## 24. 五分钟现场演示脚本

### 24.1 0:00-0:30 进入产品

- 打开网站，立即进入“我的家”；
- 评委看到客厅为中心的语义地图；
- 充电器位置变化出现一次轻量脉冲；
- 首页同时有钥匙、遥控器、阅读进度和快递记忆。

评委理解：这是一个已经运行一段时间的现实记忆产品。

### 24.2 0:30-1:30 查看充电器

- 点击充电器变化；
- 看到当前位置“工作桌下方”；
- 查看“可能从桌上掉到了下面”；
- 展开依据，看到 10:16 与 10:18 两次观察。

评委理解：Reality 保存的是结构化变化，而不是录像。

### 24.3 1:30-2:30 回拨现实

- 进入完整回拨；
- 拖动时间轴到 10:15；
- 充电器回到工作桌；
- 使用事件按钮切换到掉落和桌下状态；
- 点击低存在感的“回到现在”。

评委理解：现实状态可以回看，但用户不需要理解 Git。

### 24.4 2:30-3:30 问问与 Glass

- 进入问问或使用底部命令栏；
- 通过麦克风模拟询问“我的充电器在哪里？”；
- 查询结果返回工作桌下方；
- 点击“戴上眼镜查看”；
- 第一视角 HUD 显示向下箭头和自然答案。

评委理解：Web 中的记忆能在现实中及时提供帮助。

### 24.5 3:30-4:15 隐私控制

- 返回 Web；
- 一键暂停现实记录；
- 地图停止产生新变化；
- Glass 显示“现实记录已暂停”；
- 可选展示卫生间“当前空间已禁采”。

评委理解：隐私控制是系统运行逻辑，不是宣传文字。

### 24.6 4:15-5:00 自由探索与商业价值

- 查看记忆、设备或开放能力；
- 设备页显示“Reality 订阅有效”；
- 开放能力页展示多硬件连接同一份记忆；
- 不展示价格和复杂架构。

评委理解：产品可以从找物扩展到任务、偏好、进度和更多硬件。

## 25. 核心验收标准

### 25.1 产品理解

- 首次进入无需教程即可识别“我的家”和可询问入口；
- 评委能够发现并打开充电器变化；
- 评委能够理解当前状态与历史事件的区别；
- 评委不会把产品误解为家庭监控或照片记录工具。

### 25.2 核心交互

- 能查看充电器移动时间线；
- 能拖动时间轴并使用前后事件按钮；
- 能回到现在；
- 能通过文字或模拟语音查询；
- 能进入 Glass 第一视角模式；
- 能一键暂停；
- 能进入纠正和忘记操作。

### 25.3 响应式

- 笔记本浏览器上地图、详情和时间线无重叠；
- 390px 与 360px 宽度下文本、按钮和导航不溢出；
- 手机竖屏可以完整走通英雄流程；
- 虚拟键盘不会遮挡查询操作；
- Glass 第一视角在桌面和手机上都能正确全屏展示。

### 25.4 视觉与信任

- 产品呈现安静可信、高端克制；
- 不依赖大面积深色、霓虹或科幻装饰；
- 不确定性通过统一视觉语言表达；
- 原始证据删除后不出现伪造照片；
- 暂停和禁采状态明确且优先级足够高。

1. 绘制桌面端“现在”首页低保真线框；

4. 绘制桌面和手机回拨页面；
5. 绘制问问与查询结果；
6. 绘制 Glass 找物、暂停、禁采三联屏；
7. 绘制记忆、设备、隐私和开放能力次级页面；
8. 建立视觉 Token、字体、图标、线型和动效规范；
9. 制作第一视角与物品视觉素材；
10. 进入响应式实现与跨尺寸视觉验证。

## 27. 最终产品判断

Reality 的核心不是保存用户生活，而是帮助用户找回现实状态，并让用户始终掌握记忆边界。

Web 负责让用户查看、回拨、询问、纠正和控制完整现实记忆；Glass 只在用户真正需要时，提供眼前最短、最直接的答案。

产品最终需要给人的感觉不是“AI 在观察我”，而是：

> 我需要的时候，Reality 记得；我不需要的时候，它保持安静。
