# RealGit 前端设想与多方案草稿

> 文档版本：v0.1  
> 日期：2026-07-24  
> 范围：手机 / 家庭显示终端 + Glass AIUI  
> 暂不展开：机器人动作与具身交互  
> 文档性质：概念设计与方案发散，不是最终视觉稿或研发规格

---

## 1. 这套前端真正要表达什么

RealGit 不是记录工具。它不以“用户主动录入一条信息”为基本单位，而是持续形成对现实世界的理解：

- 人、物、空间、行为、偏好与任务持续变化；
- 模型先产生候选，经过多次观察、规则和用户纠正后形成事件；
- 事件流可以重算出某个对象在某个时刻的最佳状态；
- 记忆有来源、可信度、新鲜度、冲突、纠正、删除和版本；
- 原始媒体短时处理后删除，长期留下的是可解释的结构化现实记忆。

因此，前端不能只是把对象、耗材、偏好、任务分别做成几块列表。那会把一个“现实记忆引擎”退化成家庭资产管理软件。

前端应该让用户感受到四件事：

1. **AI 此刻认为现实是什么样。**
2. **现实从过去到现在发生了哪些变化。**
3. **AI 的理解如何逐渐形成，哪里确定，哪里仍然模糊。**
4. **当用户产生意图时，这些记忆如何在恰当时机转化为帮助。**

一句话定义：

> 手机端是用户审视、回拨和修正 AI 现实模型的界面；Glass 是 AI 在现实情境中进行最小必要干预的界面。

## 2. 两个终端不是同一个页面的大小版本

### 2.1 手机 / 家庭终端

适合承载：

- 对现实模型的浏览和探索；
- 空间、时间、人物、关系和意图之间的切换；
- 当前状态与历史版本；
- 候选、冲突和纠错；
- 隐私、删除、审计和设备管理；
- 长时间停留与更复杂的交互。

它的核心价值是：**看见 AI 如何理解我的现实世界。**

### 2.2 Glass AIUI

适合承载：

- 用户主动询问后的最短答案；
- 与当前意图直接相关的一个提醒；
- 一个可以立刻执行或确认的动作；
- 采集、暂停、禁采和错误等系统状态；
- 可选的短语音。

它的核心价值是：**此刻只补充用户缺失的那一小块信息。**

Glass 不承担：

- 记忆浏览；
- 完整时间线；
- 历史版本比较；
- 长列表；
- 审计解释；
- 普通状态变化通知；
- 为了“丰富”而增加的信息。

## 3. 手机端设计的共同原则

无论最后选择哪一种设计母题，手机端都应该遵循以下原则。

### 3.1 默认呈现投影，不呈现数据表

用户首先看到的是：

> 钥匙现在在客厅茶几右侧。

而不是：

> `location = place_483`、`confidence = 0.91`、`event_type = MOVED`

内部字段只在调试和深层审计中出现。

### 3.2 先展示“变化”，再展示“库存”

现实记忆最有价值的是发生了什么变化：

- 从哪里移动到哪里；
- 什么时候开封；
- 最近是否被使用；
- 偏好何时被表达或修正；
- 任务从未完成变为完成；
- AI 的判断何时被用户纠正。

一张静态的全物品清单很快会失去吸引力。

### 3.3 地图不是三维建模

首版地图应该是语义地图：

```text
家
├─ 玄关
│  ├─ 鞋柜
│  └─ 挂衣区
├─ 客厅
│  ├─ 茶几
│  └─ 电视柜
└─ 洗衣区
   ├─ 洗衣机
   └─ 耗材架
```

它表达空间层级、相对位置和关系，不要求精确户型、坐标或 3D 模型。

### 3.4 版本不是一份份全屋快照

“回拨现实”不代表保存每一秒的完整世界副本。正确做法是：

- 先选择对象、空间、人物或活动；
- 再沿该范围的事件流回拨；
- 由事件重算所选时刻的状态；
- 只显示与当前问题有关的变化。

### 3.5 不确定性要成为视觉语法

建议使用统一语法：

- 实线：已确认或高可信主线；
- 虚线：系统推断；
- 半透明：仍在候选期；
- 分叉：存在冲突版本；
- 褪色：状态已经陈旧；
- 小型“人”标记：用户明确确认或纠正；
- 删除后的空白节点：只保留最小删除回执，不恢复内容。

置信度不应只显示为一个百分数。

### 3.6 原始媒体删除后不伪造相册体验

可以生成隐私友好的语义草图、图标和相对位置示意，但不能让用户误以为系统仍然保留已删除的原始照片。

## 4. 手机方案 A：Reality Atlas / 现实图谱

### 4.1 核心隐喻

把用户的现实世界做成一张会逐渐生长的语义地图。

空间是骨架，物品和人物是地图上的对象，最近变化是脉冲，时间轴可以让地图回到过去。

### 4.2 首页草稿

```text
┌─────────────────────────────┐
│ 家 · 现在             记录中 ● │
│                             │
│      ┌──── 客厅 ────┐       │
│      │ 茶几  ·钥匙  │       │
│ 玄关 │ 电视柜       │  洗衣区 │
│      └──────────────┘       │
│          ↑ 今天有一次移动     │
│                             │
│ ── 昨天 ───── 现在 ──────── │
│        [问问这个世界……]       │
└─────────────────────────────┘
```

### 4.3 交互

- 双指或点击从“家”进入“房间”，再进入家具、容器和对象；
- 地图只显示稳定对象和有意义的变化；
- 时间轴回拨当前选中的空间或对象；
- 点击脉冲，看到“今天 16:30，钥匙从玄关移动到茶几”；
- 长按对象，可以确认、纠正、忘记或查看依据；
- 地图未知部分以柔和的“未形成稳定记忆”状态存在。

### 4.4 优点

- 最直接表达 Place 层级与物品位置；
- 找物场景非常自然；
- “地图逐渐长出来”能表达记忆引擎持续学习；
- 适合迁移到平板、家庭中控屏和更大的显示终端。

### 4.5 风险

- 偏好、任务和人物关系不天然属于空间；
- 如果地图上对象过多，会退化成杂乱的家庭资产图；
- 用户可能误以为地图拥有精确坐标；
- 大量小物品必须默认折叠。

### 4.6 适用结论

适合作为产品的**空间骨架**，但不能单独承担整个记忆产品。

## 5. 手机方案 B：Memory River / 记忆河流

### 5.1 核心隐喻

现实不是一张静态地图，而是一条由“变化事件”构成的河流。

首页以时间和生活片段组织内容，不按对象类型分栏目。

### 5.2 首页草稿

```text
┌─────────────────────────────┐
│ 今天                         │
│                             │
│ 08:10  准备出门              │
│        钥匙从茶几被拿起        │
│        黑色外套被穿着          │
│        ───────────────       │
│ 13:20  午餐                  │
│        记录：不喜欢这家的面     │
│        ───────────────       │
│ 20:40  洗衣                  │
│        洗衣液余量进入“低”       │
│                             │
│ [按人] [按地点] [按事件回看]    │
└─────────────────────────────┘
```

### 5.3 交互

- 系统把密集事件自动聚合为“出门”“洗衣”“阅读”等生活片段；
- 用户可以从片段进入相关人物、物品和空间；
- 拖动时间轴查看某一对象或空间的演变；
- 同一个事件片段中可以同时包含物品、行为、偏好和任务。

### 5.4 优点

- 最能表达“记忆”而不是“库存”；
- 偏好、任务、物品和活动可以自然出现在同一片段；
- 有叙事感，比分类列表更有吸引力；
- 适合回答“最近发生了什么”。

### 5.5 风险

- 事件多时容易变成另一种信息流；
- 当前状态不如地图直观；
- 自动聚合生活片段的算法如果不准，会产生奇怪叙事；
- 用户找一个具体物品时路径可能更长。

### 5.6 适用结论

适合作为产品的**时间与故事层**，不适合单独作为当前状态入口。

## 6. 手机方案 C：World Versions / 现实版本

### 6.1 核心隐喻

把现实理解为一个持续更新的版本系统：

- 当前版本；
- 最近变化；
- 候选分支；
- 用户修正；
- 被替代的旧判断；
- 可重算的历史状态。

它有一点像现实世界的版本控制，但不能直接使用工程工具语言。

### 6.2 对象页草稿

```text
┌─────────────────────────────┐
│ 钥匙                         │
│ 当前版本                     │
│ ● 客厅 · 茶几右侧             │
│   今天 16:30 · 较可信          │
│                              │
│ 版本轨迹                      │
│ 玄关柜 ───────┐               │
│               ├─→ 茶几右侧 ●  │
│ 电视柜  ······┘ 候选已过期      │
│                              │
│ [确认当前状态] [纠正] [忘记]    │
└─────────────────────────────┘
```

### 6.3 交互

- 默认只看当前状态；
- 上划展开版本轨迹；
- 冲突时显示两条候选分支，但不假装它们都是真实历史；
- 用户纠正会形成新版本，并标明“由你修正”；
- 可以选择一个时间点，查看当时的状态投影；
- 系统解释原始证据是否已删除。

### 6.4 优点

- 最能表现引擎状态、主线、候选、冲突和纠错；
- 产品差异非常明显，不像普通记录软件；
- 适合建立用户信任；
- 与底层事件模型天然一致。

### 6.5 风险

- 容易显得技术化；
- 用户不一定对普通物品的所有版本感兴趣；
- 如果首页就显示分支和置信度，会增加认知负担；
- 需要把“版本控制”翻译成人类语言。

### 6.6 适用结论

适合作为产品的**可信度与深层详情模式**，不适合成为所有用户的默认首页。

---

## 7. 手机方案 D：Intent Stage / 意图舞台

### 7.1 核心隐喻

用户不是为了浏览记忆而打开 App，而是为了完成现实中的一件事。

首页围绕当前目标生成：

- 我要出门；
- 我要洗衣服；
- 周末要旅行；
- 帮我找东西；
- 看看家里最近缺什么；
- 我想回忆上周发生的事。

### 7.2 首页草稿

```text
┌─────────────────────────────┐
│ 你现在想做什么？               │
│                              │
│         [准备出门]             │
│   [洗衣服]       [找东西]       │
│         [周末旅行]             │
│                              │
│ 可能与你有关                   │
│ · 洗衣液余量低                 │
│ · 明天取快递                   │
│                              │
│ [直接说出你的意图……]           │
└─────────────────────────────┘
```

### 7.3 交互

- 用户用自然语言或快捷意图开始；
- 系统从空间、物品、偏好、任务和时间中生成一张临时现实视图；
- “准备出门”只突出钥匙、手机、包、天气相关衣物和未完成提醒；
- “洗衣服”只突出洗衣机状态、耗材、衣物和相关任务；
- 任务完成后视图自动结束，不长期占据首页。

### 7.4 优点

- 直接把记忆转化为现实价值；
- 与主动 Agent 和 Glass 的意图判断高度一致；
- 不需要用户理解数据结构；
- 每次打开都可能生成不同但相关的界面。

### 7.5 风险

- 意图识别错误时体验会很差；
- 用户只是想随便探索时缺少稳定入口；
- 早期记忆不完整时，生成视图可能空洞；
- 不能替代隐私、审计和纠错入口。

### 7.6 适用结论

适合作为产品的**行动层和未来方向**，早期应作为镜头叠加在地图和时间线上，而不是独立承担全部导航。

## 8. 手机方案 E：Memory Constellation / 记忆星图

### 8.1 核心隐喻

现实记忆不是文件夹，而是关系网络：

- 人与常用物品；
- 人与偏好；
- 物品与空间；
- 行为与时间；
- 任务与人物；
- 一次事件与之后形成的习惯。

用户看到的是一个会聚合、分离和变强的关系场。

### 8.2 草稿

```text
                   [钥匙]
                      │ 常带
 [玄关] ── 出门 ── [我] ── 偏好 ── [清淡口味]
                      │
                   [黑色外套]
                      │ 常穿
                   [工作日]
```

### 8.3 优点

- 能承载偏好、人物、任务和物品，不被空间限制；
- 有很强的“AI 正在理解我”的视觉感；
- 适合发现长期习惯和隐藏关联；
- 与未来个人 Agent 和家庭机器人扩展自然衔接。

### 8.4 风险

- 自由节点图在手机上容易难用；
- 容易变成只适合演示、实际找不到东西的视觉效果；
- 关系推断涉及更高的隐私敏感度；
- 需要严格控制默认显示范围。

### 8.5 适用结论

适合作为后期的**人物、偏好和关系镜头**，不建议作为首版主界面。

## 9. 五种方案对比

| 方案 | 最强表达 | 最适合的场景 | 主要弱点 | 建议角色 |
|---|---|---|---|---|
| Reality Atlas | 空间与当前状态 | 找物、空间变化 | 难承载偏好与任务 | 主骨架 |
| Memory River | 时间与生活片段 | 回忆、最近变化 | 容易变成信息流 | 时间层 |
| World Versions | 引擎、版本、纠错 | 信任、冲突、审计 | 偏技术化 | 深层详情 |
| Intent Stage | 记忆转化为行动 | 出门、洗衣、旅行 | 依赖意图判断 | 动态镜头 |
| Memory Constellation | 人物与关系 | 偏好、习惯、关系 | 手机可用性风险 | 后期扩展 |

## 10. 推荐方向：Reality Canvas / 现实画布

不建议五选一。推荐以 **Reality Atlas 为稳定骨架**，吸收另外三种最有价值的能力：

```text
Reality Atlas      提供“现在在哪里”
+ Memory River     提供“发生了什么”
+ World Versions   提供“为什么相信它”
+ Intent Stage     提供“现在能帮我什么”
= Reality Canvas
```

Memory Constellation 暂时作为未来的人物与偏好镜头。

### 10.1 推荐的主导航

不按“物品 / 耗材 / 偏好 / 任务”分类，而只保留三个入口：

1. **现在**：AI 当前理解的现实画布；
2. **回拨**：按对象、空间、人物或活动查看变化；
3. **问**：通过自然语言生成一个与当前意图相关的现实镜头。

设备、隐私、审计、纠错不占据底部主导航，而从全局状态入口和对象详情进入。

### 10.2 “现在”首页文字线框

```text
┌───────────────────────────────┐
│ 家 · 周四晚间         现实记录中 ● │
│ AI 的现实模型已更新于 2 分钟前       │
│                               │
│        ┌──── 客厅 ────┐       │
│ 玄关   │  茶几 ·钥匙   │   洗衣区 │
│ 近期   │  沙发 ·遥控器  │   余量低  │
│ 变化 ● └──────────────┘      ● │
│                               │
│ 这段时间发生了什么              │
│ 16:30  钥匙移动到茶几右侧         │
│ 20:40  洗衣液进入低余量           │
│                               │
│     [按住说话 / 问问这个世界]      │
│  现在             回拨            问 │
└───────────────────────────────┘
```

这里仍然可能有卡片，但卡片不是产品的结构。真正的结构是一个可缩放、可回拨、可切换镜头的现实画布。

### 10.3 对象详情文字线框

```text
┌───────────────────────────────┐
│ ← 钥匙                         │
│                               │
│ 当前状态                        │
│ 客厅 · 茶几 · 右侧               │
│ 今天 16:30 · 较可信 · 眼镜观察     │
│                               │
│ ── 玄关 ─────────→ 茶几 ●        │
│    08:10          16:30          │
│                               │
│ 为什么这样判断                   │
│ 两次观察一致，尚未由你确认          │
│ 原始图像已按策略删除               │
│                               │
│ [确认] [纠正位置] [查看完整变化]     │
│ [忘记这条记忆]                    │
└───────────────────────────────┘
```

### 10.4 “回拨”模式

进入回拨前必须选择范围：

- 一个对象；
- 一个房间；
- 一个人；
- 一次活动；
- 一个时间窗。

回拨时，画布只重算该范围的状态，不模拟完整世界。

```text
选择：客厅

周一 ───── 周二 ───── 周三 ───── 现在
                         ▲

本时刻的客厅：
· 钥匙仍在玄关
· 花瓶在餐桌
· 遥控器状态未知

从这里到现在的变化：3 项
```

### 10.5 “AI 如何看见这里”模式

用户可以在任何空间或对象上展开一个底部面板：

```text
已形成主线      8 个对象
仍在学习        3 个候选
存在冲突        1 项
状态已陈旧      2 项
本周已删除      6 条证据
```

这不是开发者仪表盘，而是对引擎状态的人类翻译。

## 11. 三种可尝试的手机视觉方向

本轮不决定最终视觉系统，但可以用三个方向做后续草图。

### 11.1 方向一：温和制图 / Calm Cartography

**推荐作为第一轮。**

- 暖灰或纸张色背景；
- 深墨色文字；
- 空间边界像地图等高线；
- 变化事件使用少量琥珀或绿色；
- 确认、推断、候选通过线型而不是高饱和颜色区分；
- 动效像地图重新聚焦和路径生长；
- 整体安静、可信、适合长期使用。

安全选择：

- 信息层级清楚；
- 颜色克制；
- 交互遵循手机习惯；
- 不需要依赖 3D。

设计风险：

- 用“地图”而不是“列表”做首页；
- 让未知和不确定区域可见；
- 让时间路径成为主要视觉元素。

### 11.2 方向二：暗色引擎 / Living Engine

- 深灰黑背景；
- 单一荧光绿或青色强调；
- 事件轨迹、版本分支和实时状态更突出；
- 与 Rokid 单绿 Glass UI 有统一感；
- 更像一个正在运行的现实计算引擎。

优点是产品差异强，能突出“引擎”和“版本”。风险是容易像开发者控制台、科幻演示或监控系统，不够生活化。

### 11.3 方向三：生活编辑部 / Living Editorial

- 大标题、非对称排版、生活片段式叙事；
- 语义场景草图配合短句；
- 时间变化像杂志章节；
- 首页更像“今天，AI 记住了什么”。

优点是情感吸引力更强，能避免资产管理感。风险是信息效率较低，长期使用时需要一个更稳定的地图入口。

### 11.4 建议

第一轮原型可以同时画：

- 温和制图版“现在”首页；
- 暗色引擎版“对象版本”页；
- 生活编辑版“今天发生了什么”页。

这三张不是三个完整 App，而是测试产品最重要的三种气质：现实、引擎、记忆。

## 12. Glass AIUI：内容已收敛，重点是最小呈现

### 12.1 Glass 的默认状态

默认不出现任何内容。

只有以下三类情况允许占用视野：

1. 系统和隐私状态；
2. 用户主动询问；
3. 高可信、强相关、可立即行动的意图提醒。

### 12.2 主动提醒准入

```text
意图可信度
× 缺口可信度
× 记忆可信度
× 当前时机
× 行动价值
> 打扰阈值
```

任何一项不足，都保持沉默或转到手机。

### 12.3 Glass 内容模板

#### 模板 A：系统状态

```text
● 现实记录中
```

```text
现实记录已暂停
单击恢复
```

```text
当前空间已禁采
```

#### 模板 B：主动询问

用户：“钥匙在哪？”

```text
钥匙在客厅茶几右侧
今天 16:30 看到
```

不主动附加更早位置。只有用户说“没找到”或继续追问，才进入下一轮查询。

#### 模板 C：意图缺口

系统判断用户正在准备出门，并确认钥匙尚未随身：

```text
钥匙还在客厅茶几右侧
```

#### 模板 D：行为中的消耗提醒

系统观察到用户已开始洗衣，并且洗衣液余量低：

```text
洗衣液大约只够这次
[加入采购清单]
```

#### 模板 E：时间地点承诺

用户此前说“到公司提醒我把资料给小王”，系统确认已经到公司且小王在附近：

```text
记得把资料给小王
[知道了]
```

#### 模板 F：确认与纠错回执

```text
已记住：
它是书房的充电器
```

### 12.4 四种表现形式

Glass 样式空间有限，不需要为了视觉丰富而制造装饰。可以把设计集中在四种稳定表现：

#### 1. Whisper Line / 轻声字幕

- 一至两行文字；
- 无大边框；
- 自动淡入淡出；
- 用于查询答案和低干扰提醒。

#### 2. Locator / 定位指示

- 对象名称；
- 相对方向或短路径；
- 只在找物时出现；
- 不做满屏 AR 标签。

#### 3. Action Ticket / 行动票据

- 一个结论；
- 一个动作；
- 有明确有效期；
- 用于“加入清单”“确认”“暂停”等。

#### 4. Safety Shield / 安全状态

- 视觉优先级最高；
- 采集暂停、禁采、错误使用固定图形；
- 不与普通提醒共用样式。

### 12.5 图标、边框和颜文字的使用

图标和边框应该传达语义，不只是装饰：

- 圆点：系统正在运行；
- 盾牌：隐私或策略；
- 箭头：位置和方向；
- 对勾：用户已确认；
- 虚线框：等待用户动作；
- 实线框：系统状态；
- 颜文字只在明确的品牌人格中使用，不承担关键状态。

### 12.6 文字与语音

建议提供四档：

1. **仅文字**：默认；
2. **用户问话时语音回答**；
3. **高优先级提醒可语音**；
4. **完全静音，只保留系统安全状态。**

语音不应该简单朗读屏幕全文，而应该比文字更短。

### 12.7 展示时间

- 普通答案：用户看完或 3–5 秒后消失；
- 定位指示：找到对象或用户取消后消失；
- 行动票据：完成、忽略或过期后消失；
- 安全状态：状态解除前保持可见；
- 同一意图不连续重复提醒。

## 13. 两端如何共同工作

同一条现实记忆或 Signal 不应该直接绑定某个页面，而应该先生成一个与设备无关的“呈现包”：

```text
主体
+ 当前结论
+ 为什么现在相关
+ 新鲜度
+ 可信度
+ 建议动作
+ 有效期
+ 隐私级别
+ 可展开解释
```

再由终端决定表达层级：

| 层级 | 表达 |
|---|---|
| L0 | 不显示，只留在系统 |
| L1 | Glass 一句话或一个动作 |
| L2 | 手机底部面板 |
| L3 | 手机完整时间线、版本、依据和审计 |

这样未来即使接入家庭屏、音箱、车机或机器人，也不需要重新定义记忆内容，只需要新增设备的表达和行动策略。机器人本轮不展开。

## 14. 三个端到端场景

### 14.1 准备出门

```text
动作序列：
穿鞋 / 穿外套
+ 拿起手机或包
+ 向玄关移动
→ 推断“准备出门”

系统检查：
用户通常需要钥匙
+ 钥匙尚未随身
+ 钥匙位置可信
→ 允许 Glass 出现
```

Glass：

> 钥匙还在客厅茶几右侧

手机：

- 可以查看钥匙当前状态和移动路径；
- 可以纠正位置；
- 可以查看 AI 为什么形成“出门要带钥匙”的个体习惯；
- 不需要在当下把这些解释塞进 Glass。

### 14.2 洗衣

```text
抱着衣物进入洗衣区
+ 打开洗衣机 / 放入衣物
+ 洗衣液余量已低
+ 尚未加入采购清单
→ 允许提醒
```

Glass：

> 洗衣液大约只够这次  
> 加入采购清单？

手机：

- 显示余量变化趋势；
- 显示最近开封与使用；
- 可调整提醒策略；
- 采购时把多个低库存物品合并呈现。

### 14.3 回看钥匙

手机进入 Reality Canvas：

1. 搜索或点击钥匙；
2. 看到当前状态“客厅茶几右侧”；
3. 向左拖动时间轴；
4. 看到昨天仍在玄关；
5. 回到今天，看到 16:30 的移动事件；
6. 如果位置错误，拖动到正确空间或语音纠正；
7. 新纠正进入事件主线，旧判断保留为被替代版本。

## 15. 首版范围建议

### Phase 1：证明“手机能看见，Glass 能克制”

手机：

- 设备与隐私状态；
- 家庭 → 房间 → 关键对象的语义地图；
- 找物对象详情；
- 单对象时间线；
- 确认、纠正、忘记；
- 原始证据删除状态。

Glass：

- 佩戴、记录、暂停、禁采、错误；
- 用户主动找物；
- 用户主动纠错回执。

### Phase 2：证明“现实可以回拨”

- 房间级变化；
- 对象版本轨迹；
- 时间范围选择；
- 现实 diff；
- 候选和冲突的用户化呈现；
- “AI 如何看见这里”面板。

### Phase 3：证明“记忆可以主动服务”

- 准备出门；
- 洗衣与耗材；
- 时间地点承诺；
- 影子模式评估意图准确率；
- 个体化打扰阈值；
- Glass 语音开关和提醒冷却。

### 暂不做

- 全屋 3D 数字孪生；
- 所有物品全量扫描与陈列；
- Glass 上的历史和审计；
- 大量主动提醒；
- 机器人动作编排；
- 把聊天框作为唯一首页；
- 直接把底层数据库字段暴露给普通用户。

## 17. 当前推荐与待讨论项

### 当前推荐

- 手机采用 Reality Canvas 混合方向；
- 以 Reality Atlas 作为稳定空间骨架；
- 用 Memory River 承载变化与生活片段；
- 用 World Versions 承载可信度、纠错和引擎状态；
- 用 Intent Stage 作为动态镜头，不作为唯一首页；
- Glass 保持极度克制，只呈现系统状态、主动查询和高价值意图提醒；
- 语音由用户控制，默认以短文字为主；
- 机器人仅保留统一 Signal / Action 扩展接口，本轮不设计。

### 需要后续验证

1. 用户是否愿意浏览语义地图，还是只在找东西时使用；
2. 地图逐渐生长是否能形成长期吸引力；
3. “回拨现实”对用户最有价值的范围是对象、空间还是生活片段；
4. 引擎状态应该多显性，才能既建立信任又不造成负担；
5. 偏好与任务更适合出现在人物镜头、事件片段还是意图视图；
6. Glass 主动提醒的误报容忍度；
7. 单绿 480×640 屏幕上文字、图标、边框和语音的最佳组合；
8. 同一条 Signal 在 Glass、手机和家庭屏之间如何避免重复打扰。

## 18. 最终判断

手机端最值得做的不是一个更漂亮的记录软件，而是一个**可以被回拨、被质疑、被修正的现实模型**。

Glass 最值得做的也不是更丰富的页面，而是一个**知道什么时候不说话的 AI 界面**。

两者结合后，产品才完整：

> 手机让用户看见 AI 的记忆如何形成；Glass 让这些记忆只在现实中最有价值的瞬间出现。
