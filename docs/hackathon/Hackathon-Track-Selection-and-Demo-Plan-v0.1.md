> 文档版本：v0.1

> 产品母版：[产品 PRD v1.3](../product/RealGit-PRD-v1.3.md)

## 0. 两个结论

**赛道选择的结论**：优先选「看重真实世界、真实硬件、长期架构」的赛道，避开纯创意与纯美学赛道。
本项目的差异化是**真硬件 + 真多模态 + 已跑通的端云链路 + 一套认真的隐私与事件溯源架构**，
在「谁的点子更妙」的赛道上这些优势不加分。

**演示设计的结论**：

> **只有「现实进入系统」这一段必须是真的，其余全部可以是假的。**

评委在现场见到的绝大多数作品是「网页 → LLM → 网页」。本项目唯一无法被 5 分钟复刻的，
是**眼镜真的看到了那个东西，云端真的沉淀出了结构化记忆**。这一段一旦用 mock，护城河当场归零；
反过来，物品网格、时间线动画、隐私开关这些 mock 得漂亮反而更好，真做出来评委也分辨不出真假。

## 2. 赛道匹配结论

### 2.1 第一档：现有代码直接命中，改动趋近于零

#### ① #10 DIMENENSIONAL「Agents 不应该只存在屏幕里」— 最强匹配

赛题原话是「从未运行过电机、推开门、用自己的『眼睛』看过真实世界」。
本项目就是给 Agent 装眼睛，且是 Agent 主动驱动——PRD §8.2 已列出触发来源
「外部触发：家庭设备事件或 Agent 请求一次现场确认」。

- **Demo 脚本**：用户问「我钥匙呢」→ 记忆置信度不足 → Agent 主动下发 CaptureIntent 让眼镜看一眼 → 回答。
  这是「Agent 伸手去够现实」，不是「Agent 查数据库」。
- **缺口**：没有执行器，赛题的「运行电机、推开门」占不到。
- **最小增量**：[agent-gateway/tools.py](../../services/agent-gateway/app/tools.py) 加一个
  `request_live_capture` tool，串到下行通道。约 1 天。

#### ② #23 zilo「从指尖出发，探索伴身智能」

已有一枚功能等价的戒指（六轴 IMU、麦克风、按键），Zilo Whisper 参数几乎一致。
按既有架构这是**写一个 Device Adapter**，记忆本体一行不改。

- **Demo**：按戒指说一句 → 灵感/任务落库 →（可选）眼镜 TTS 回读。
- **风险**：需拿到 Zilo 实物 + SDK。**先确认设备发放规则。**

#### ③ #3 灵光「见自己 —— 先为自己 Vibe」

[06 号文档 §1.1](../architecture/06-Idea-Capture-Sidecar-Architecture.md) 写的是
「灵感捕捉真正贵的部分不是存储，是**想到的那一刻手不方便**」——这是自身痛点，不是调研出来的用户痛点。
07 号文档里「为什么灵感的价值来自稀缺，证明却来自公开」更是原始困惑本身。

- **优势**：零硬件依赖，纯软件可交付，叙事完成度最高。
- **代价**：06 号文档批次 A–F 要真做出来（四张表 + idea-worker + API）。约 3–5 天。
- **顺带**：修掉 [projections.py:61](../../services/memory-platform/app/memory/projections.py:61) 的
  `fold_task_events` 覆盖缺陷——那是真 bug，与比赛无关也该修。

### 2.2 第二档：需加一个明确的小功能才够格，但每个都填补真实架构缺口

#### ④ #2 清闲 LiberNovo「Desktop Daemon」

[分层架构 §1](../architecture/README.md) 明说「网关是逻辑角色，可以运行在眼镜、手机或**未来家庭 Hub** 上」。
这台机器就是那个 Hub。更关键的是 [07 号文档 §5.5](../architecture/concepts/07-Idea-Provenance-and-Encrypted-Matching.md)
的硬约束——**embedding 可被反演，必须视为等同明文，不能出信任域**。
一台桌面常驻机让「记忆不出家门」从口号变成事实。

- **最小增量**：Memory Platform 打成本地部署包 + 夜间批处理（睡觉时消化感知积压 `pending_outbox`）。
- **额外收益**：赛道送机器，且这个方向迟早要做。

#### ⑤ #21 涂鸦 tuya「破界者：用 AI 重写生活脚本」

「解决一个真实的生活问题」——找钥匙、洗发水快用完了，就是原教旨的真实生活问题，
且正是 PRD §6 的两个 P0 场景。软硬结合的要求天然满足。

- **最小增量**：接一两个涂鸦设备作为 PRD §8.1 的「结构化事件」输入源
  （门锁/传感器直接进候选链，架构已留口）。约 1–2 天。

#### ⑥ #1 Injective x AI 创新赛道

[07 号文档 §7.4](../architecture/concepts/07-Idea-Provenance-and-Encrypted-Matching.md)
已列出 Injective agent-skills 的落点表（`injective-evm-developer` 写锚定/托管合约、
`injective-frontend-wallet` 做签名）。Phase 0（加盐 hash + JCS canonical）+
Phase 1（daily Merkle root 上链）是几十行到几百行的量。

- **但 07 号文档自己反对过**：§7.4 明确写了「引入加密货币基础设施与 RealGit 的
  家庭隐私叙事相反，若真要做，**做成独立产品线、独立 App、独立品牌**」。
- **判断**：hackathon 恰好是那个独立分支该存在的地方。用「灵感存在性证明」单独立项，
  与主产品只共享导出接口。**不要**把 RealGit 主体包装成区块链项目。

| #16 秒哒美学、#5 智能少年、#6 亚马逊 | 太泛，真硬件 + 严肃架构的优势在这里不加分 |

### 2.4 边缘可选

| 赛道 | 说明 |
|---|---|
| #24 Photon 消息即界面 | 下行通道改投 iMessage/WhatsApp，一天工作量。但 PRD §9 限定「不代替用户发送任意消息」，只能给自己发提醒 |

**#10 + #3 + #2。**

三者共用同一份代码的不同切面（Agent 触达现实 / 灵感捕捉 / 本地信任域），不需要三套 demo；

**先去确认 Zilo 和涂鸦的设备发放规则**，能拿到就补进来，拿不到不影响主线。

## 4. 三段式演示脚本

### 4.1 第 1 段（90 秒）— 必须实时，不可替代

**「眼镜看一眼，云端就记住了」**

```text
戴上眼镜 → 现场把某个物品放到某处 → 眼镜采集
  → 联调页左侧实时画面
  → 右侧 4 秒后出现 caption / scene_tags / 证据缩略图
  → 手机或网页问「X 在哪」
  → 返回语义位置 + 时间 + 置信度
```

- **为何必须实时**：这是全场唯一「真实世界 → 结构化记忆」的闭环，
  也是唯一能让评委相信后面所有内容的锚点。
- **最大风险**：k3 VLM + CLIP 单帧处理是秒级，会场网络更不确定。
  **必须先 `adb forward tcp:8090 tcp:8090` 走 USB，不碰会场 WiFi**
  （联调页默认地址 `http://127.0.0.1:8090/stream` 就是 USB 模式）。

### 4.2 第 2 段（2 分钟）— 半实时：真后端 + 预热数据

演示的是「记忆的性质」，不是「采集的性质」，数据可以是**开场前 10 分钟现场采的**，不必台上现采。

| 演示点 | 形式 | 说明 |
|---|---|---|
| 同一物品换了位置 → 时间线 | 真后端，预热数据 | 展示 append-only 事件流，不是覆盖 |
| 「不对，钥匙在玄关」→ 纠正 | **实时** | `POST /correct` 后立刻重查，结果变了。3 秒交互，风险低、冲击力大 |
| 删除最近 5 分钟 → 再查，查不到 | **实时** | `forget-recent` + 审计留痕。**隐私叙事的杀手锏，必须真做** |
| 未授权 Agent 访问 → 403 + 审计记录 | 真后端，1 条命令 | 30 秒，证明这不是玩具 |
| CLIP 场景检索「找一张有笔记本电脑的桌子」 | 真后端，`data/frames/` 7 张实拍 | 该批数据有 ground truth，稳 |

### 4.3 第 3 段（1 分钟）— 可以全 mock，且应该 mock

| 演示点 | 为什么 mock 没问题 |
|---|---|
| 物品网格 / 房间视图 / 「所有物品 N 件」 | 数量感是氛围，真假不可辨。现在 `itemSeeds` 已在做这件事 |
| 耗材余量下降曲线 + 低库存提醒 | 趋势预测需要多天连续观测，**hackathon 物理上不可能真跑**。用预置曲线，并诚实说明「这是 7 天数据的形态」 |
| 阅读进度 / 衣橱渐进记忆 | PRD 的 P1/P2 场景，讲愿景即可 |
| 眼镜端 TTS 提醒呈现 | 可以真（下行通道已通），时间紧则播录屏更稳 |

## 5. 按赛道的差异化切片

同一套 demo，换一个 30 秒的收尾就是另一个赛道的作品。

| 赛道 | 需要新增的实时演示 | 工作量 |
|---|---|---|
| #10 DIMENENSIONAL | Agent 说「我不确定，让我看一眼」→ 主动下发 CaptureIntent → 眼镜拍 → 回答。**必须实时**，它就是赛题本身 | `agent-gateway/tools.py` 加 tool + 接下行通道，约 1 天 |
| #3 灵光·见自己 | 按键说一句灵感 → 10 秒内条目出现（06 号文档 §12 验收标准第 1 条）。**必须实时**，且当场演示「拔网线/关掉 LLM，条目依然在」——这是旁路设计的灵魂 | 批次 A–C，3–5 天 |
| #2 Desktop Daemon | 拔掉外网，全链路继续工作。**必须实时**，断网是这个赛道唯一有说服力的证明 | ASR 本地模型已有，VLM 需本地兜底，1–2 天 |
| #21 涂鸦 | 门锁事件进候选链 → 触发一次采集。可 mock 设备事件（直接 POST 结构化事件），赛题看的是「解决真实生活问题」而非「设备真连上了」 | 半天 |

| #23 zilo | 戒指按键 → 采集。**必须实时**，否则等于没参加 | 取决于能否拿到设备 |

## 6. 兜底阶梯

**这一节比上面所有内容都重要。** 演示事故约八成来自网络和设备。
准备四级降级，每级切换不超过 10 秒：

```text
L0  眼镜实时 USB 串流 + 现场采集 + 真 LLM            ← 首选
L1  眼镜断了 → 手机拍照 POST /internal/v1/envelopes  ← 采集端降级，后端仍真
L2  外网断了 → 本地 ASR + 预置 caption 回放          ← LLM 降级
L3  全挂 → 播录屏                                    ← 最后防线
```

### 会场前准备清单

1. **提前把 `rme_demo` 库跑满**——前一晚各跑一遍
   [`multimodal_e2e_find_object.py`](../../services/memory-platform/scripts/multimodal_e2e_find_object.py)
   与 [`real_frames_scene_search_demo.py`](../../services/memory-platform/scripts/real_frames_scene_search_demo.py)，
   向量和投影全部落库。**台上只做增量，不做冷启动。**
2. **录一段 L0 的完整录屏**，含时间戳。真出事时说「网络原因，这是 10 分钟前的实录」，
   比现场手忙脚乱强十倍。
3. **准备一个「假的实时」检测点**——让评委指定一个物品当场放。
   这比任何技术讲解都有说服力，也是与 mock 作品的分水岭。
4. **不在台上做冷 ingest 长尾**。7 帧全量处理是分钟级，只演示 1–2 帧的增量。
5. USB 线、`adb forward` 命令、眼镜电量、备用手机，全部前一晚验一遍。

## 7. 一条反直觉的建议

**主动指出哪些是 mock。**

评委见惯了「全是真的」的说辞。上台说「物品网格是演示数据，耗材曲线是 7 天数据的形态，
但从这里到这里是刚才当场发生的」——这个诚实度本身就是差异化，
且它与项目核心叙事（模型产生候选、事件构成事实、一切可审计）完全同构。
**PRD §4.2 的原则如果连 demo 都不遵守，评委会闻出来。**
