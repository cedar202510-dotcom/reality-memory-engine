Reality Memory Engine 工程链路可视化 v1.3

这页把完整 PRD 拆成可读的工程地图：谁采集、谁解析、谁决定事实、什么会被长期保存、什么只是短暂证据，以及每种模态进入同一套记忆结构的方式。

一个手机 App账号、配对、策略、加密队列、上传、管理和提醒的默认网关。
两个 Rokid 路径CXR-L 是过渡 Adapter；RV101 原生 Runtime 是最终眼镜采集端。
一套观察契约图片、短视频、音频、传感器和结构化事件都输出 AtomicObservation。
一个事实源只有 MemoryEvent 是事实；Projection、索引和 Signal 都可重算。

1. 总链路

这条链路从设备事件开始，到结构化记忆和提醒结束。模型只负责解析和候选，不能直接写事实。

采集入口

Device Adapter

  • Rokid CXR-L Adapter
  • RV101 Native Runtime
  • Ring BLE Adapter
  • Future Hardware Adapter
统一网关

Reality Mobile Gateway

  • 账号与家庭域归属
  • Session / Policy
  • 加密队列与上传
  • 设备审计与删除回执
短暂证据

Source + Evidence

  • SourceEnvelope 统一来源
  • EvidenceItem 媒体证据
  • 结构化设备事件可无媒体
  • TTL 与敏感标签
理解与聚合

Perception + Fusion

  • 按模态选择解析器
  • 输出 AtomicObservation
  • 聚合为 Bundle / Segment / Episode
  • 形成 MemoryCandidate
事实与使用

Memory Core

  • 实体归并与冲突处理
  • 追加 MemoryEvent
  • 重算 StateProjection
  • Query / Signal / Reminder
最重要的边界：原始图片、短视频、音频不是长期记忆；长期事实只来自经过门控后追加的 MemoryEvent。

3. 模态如何进入同一套结构

模态 触发原则 解析器输出 关键限制
单图 显式触发、固定间隔、场景变化、对象拿放、阅读低频记录。 对象、位置、容器关系、余量、页码、场景摘要、敏感标签。 策略通过前不得启动相机；完成结构化后删除 Evidence。
前后帧 运动峰值、对象被拿起或放下、容器开合。 状态变化、对象从 A 到 B 的低成本动作证据。 只表达短窗变化，不把每帧都沉淀成实体。
2-3 秒短视频 静态图歧义、动作过快、倒出或快速移动。 连续动作、短时轨迹、关键帧和运动关系。 不录长视频，不接连续视频流，受单会话预算约束。
短音频 戒指/眼镜显式触发，或会话内本地 VAD 命中连续人声。 ASR、偏好、任务、纠正、命名、少量环境声音事件。 静音不落盘、不上传、不进 ASR；自动 VAD 单段最长 15 秒。
传感器 IMU 峰值、佩戴/摘下、折叠、按键、低电量、过热。 运动强度、姿态、手势、设备状态和安全边界。 主要用于调度和门控，通常不单独形成长期事实。
结构化事件 手机确认、智能家居、日历、门锁、用户手动输入。 确认、纠正、外部状态、设备事件或用户意图。 仍必须有 SourceEnvelope、策略快照、幂等键和审计。

4. 数据对象中英对照

这些英文对象可以作为代码对象名；中文解释帮助理解它在链路里的层级。

SourceEnvelope

来源信封

一次设备或用户入口事件的统一包装，记录来源、时间、策略、触发方式和 Evidence 引用。

不是事实。

EvidenceItem

短暂证据

图片、短视频、短音频或传感器窗口。只为结构化服务，完成后删除。

不是事实。

AtomicObservation

原子观察

单个解析器输出的最小结构化观察，带模型版本、置信度和证据引用。

不是事实。

ObservationBundle

观察包

把同一时间窗或同一现实变化下的多个原子观察关联起来。

不是事实。

ActionSegment

动作片段

几秒到几分钟的局部动作，例如拿起、切菜、放下、等待。

不是事实。

ActivityEpisode

活动段

目标相对稳定的一段活动，例如做饭、收拾厨房、准备出门。

不是事实。

MemoryCandidate

记忆候选

可能成为记忆事实的现实断言，例如“钥匙可能在茶几右侧”。

待决候选。

MemoryEvent

记忆事件

追加式事实变化。纠正通过新事件表达，不直接改旧事件正文。

唯一事实源。

StateProjection

状态投影

从有效事件流计算出的当前最佳状态，例如当前位置、余量、任务状态。

可重算派生数据。

SignalCandidate

信号候选

可能值得提醒的状态变化，例如低库存或置信冲突。

不是事实。

ReminderDecision

提醒决策

判断是否提醒、何时提醒、在哪个终端提醒、措辞如何。

受控行动。

PolicySnapshot

策略快照

当前采集、处理、留存和调用权限的版本化快照。

审计依据。

5. Session 与 Episode 的区别

Source Session

设备或连接层会话，例如一次佩戴、一次 CXR-L 连接、一次手机采集 Session。

  • 由设备生命周期决定
  • 用于采集、审计、策略和幂等
  • 摘下、断连、关闭会结束或暂停

Activity Episode

现实活动层会话，例如做晚饭、收拾厨房、准备出门。

  • 由目标、物体、空间、动作变化决定
  • 可以跨多个采集 tick
  • 位置变化不一定结束 Episode

Action Segment

Episode 内部的局部动作，例如切菜、拿钥匙、打开抽屉。

  • 比 Episode 更细
  • 可用于判断动作连续性
  • 帮助形成 MemoryCandidate
例子：用户在厨房台面、冰箱和灶台之间移动，通常仍是“做晚饭”Episode；如果放下锅开始擦地，才可能切到“清洁厨房”。

6. 关键规则

PolicyCheck 在前

每次调用 CameraX、VideoCapture 或 AudioRecord 前，必须检查用户、设备、Session、模态、触发来源、位置、电量、温度、网络和预算。

动态优先级

显式意图、运动变化、场景新颖性、记忆价值和不确定性降低会提高优先级；隐私风险、电量、温升和日预算压力会降低优先级。

频率不是固定真理

PoC 测 5、15、30、60 秒。产品化后应按场景变化调整：高运动 2-5 秒，普通走动 15-30 秒，阅读 3-5 分钟，休息降频或暂停。

两种触发

显式语音由戒指、眼镜按键或明确指令触发；会话内 VAD 只在授权现实记录且音频策略允许时运行。

短片段

推荐预滚不超过 500 ms，连续静音 800-1200 ms 后结束，自动 VAD 单段最长 15 秒。

静音不沉淀

静音缓冲不落盘、不上传、不进入 ASR。CXR-L 阶段在手机本地 VAD；最终在眼镜端 AudioRecord + VAD。

边界信号

目标变化、空间变化、物体集合变化、社会情境变化、时间空档和预测误差共同决定是否切换 Episode。

迟滞

一次模糊图片不应立刻结束 Episode。中间状态先标记为 tentative，连续证据支持后再提交。

中断不是结束

接电话、等水烧开、短暂离开都可能只是 suspended。后续上下文匹配时恢复原 Episode。

Evidence TTL

正式图片本地最长 10 分钟、云端最长 15 分钟；短音频和短视频同样是短暂证据，结构化完成即删。

删除覆盖全链路

删除必须覆盖本地证据、对象存储、观察、候选、事件有效性、投影、索引、缓存、信号和异步任务。

Tombstone 最小化

删除墓碑不保存被删内容，只保存删除范围、完成状态和不可逆审计哈希。

7. API 作用地图

POST /internal/v1/sessions

创建佩戴或采集会话，绑定设备、用户、家庭域、策略快照和设备状态。

PATCH /internal/v1/sessions/{session_id}

激活、暂停、恢复、阻断或结束会话。所有状态变化进入审计。

GET /internal/v1/capture-policy

下发允许模态、触发来源、禁采上下文、预算、TTL、调试证据权限和策略签名。

POST /internal/v1/capture-attempts

记录一次采集尝试。即使没有媒体上传，也能知道设备为何尝试或为何跳过。

POST /internal/v1/evidence/init

创建临时上传授权和 Evidence 元数据，限制大小、模态、TTL 和策略版本。

POST /internal/v1/evidence/{id}/complete

标记 Evidence 上传完成，进入安全扫描、敏感检测和模态解析。

POST /internal/v1/observation-candidates

Perception 服务写入结构化观察和候选。设备端不能直接写事实主线。

POST /internal/v1/memory-events

Memory Core 在通过策略、置信度和冲突门后追加 MemoryEvent。

GET /v1/memory/objects/{id}/where-is

返回对象当前最佳位置、时间、新鲜度、置信度、备选和来源事件。

POST /v1/memory/forget-recent

执行近窗遗忘，清理证据、候选、事件有效性、投影、索引、缓存和信号。

GET /v1/memory/audit

给用户或测试者查看设备何时记录、因何触发、策略如何判断、证据是否删除。

GET / WS /v1/memory/signals

拉取或订阅可能值得提醒的状态变化。当前阶段只允许提醒，不执行外部动作。

8. 从“钥匙在哪里”看一次完整闭环

1. 采集

RV101 Runtime 或 CXR-L Adapter 获得一张受控图片，统一手机网关封装 SourceEnvelope 和 EvidenceItem。

2. 解析

Image Extractor 输出 AtomicObservation：疑似钥匙位于客厅茶几右侧，带证据引用和置信度。

3. 聚合

Temporal Fusion 将图片、上一帧、IMU 或显式触发合成 ObservationBundle，并归入一个动作片段。

4. 候选

Memory Core 形成 MemoryCandidate：实体 obj_keys_01 的 location 可能是 coffee_table/right_side。

5. 事实

候选通过身份归因、置信度和冲突检查后，追加 MemoryEvent：MOVED 或 OBSERVED_AT。

6. 查询

StateProjection 重算当前位置。用户问“钥匙在哪里”时，Query 返回位置、时间、置信度和来源事件。

7. 删除

原始图片完成结构化后删除。后续如用户近窗遗忘，候选、事件有效性、投影、索引和信号一并清理。
