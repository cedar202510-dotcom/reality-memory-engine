1. 首页应该先是 Agent，而不是物品地图。

如果产品最终是“现实记忆中台”，用户最自然的入口不是翻列表，而是问一个现实问题。首页可以是一个有生命感的语音界面，文字输入降为备选。这里的 Agent 暂叫“在场顾问”，名字可以后续再取。

用户价值不用学习数据库结构，直接问“在哪、何时、还剩多少、我喜不喜欢”。
展示内容语音入口、少量建议问题、当前感知状态、关键主动提醒。

2. 记忆不应该全部暴露，而是分层展示。

底层可以有很多 MemoryEvent，也就是“已经确认的记忆事件”。但用户不需要看全部事件流。用户要看的是当前状态、重要变化、可纠正的候选、可删除的边界。

长期记忆物品位置、空间状态、任务、偏好、阅读进度、耗材余量。
不直接展示大量相似图片、传感器原始波形、模型中间推断、无信息增量片段。

3. 可以不用传统顶部导航，但不能没有导航逻辑。

手机 App 不需要像网页一样顶部放品牌、家庭名和菜单。更好的方式是把导航变成空间结构：Agent 是入口，记忆星系是总览，今天是主动建议，控制是信任边界。形式可以更有想象力，但这四个锚点要稳定。

顾问问答、语音、主动建议。
记忆物品、空间、任务、偏好、耗材。
控制暂停、删除、禁采、设备、审计。

4. 未来智能家居能力要出现，但不要像设备管理后台。

理想态可以接入门锁、冰箱、柜子、扫地机、家居传感器和订单数据。它们不应该作为“设备列表”成为主角，而是作为现实上下文的来源，支撑 Agent 回答和提醒。

前台语言门口、厨房、药盒、耗材、到家、偏好、日程。
后台语言设备适配器、证据、观察、记忆事件、状态投影。

可探索的 Agent 命名方向

先不定名，但要避免“管家”“助理”这种太常见的词。名字应该表达它不是聊天机器人，而是对现实状态有持续理解的个人顾问。
