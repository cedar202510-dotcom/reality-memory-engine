可以迁移的三种视觉机制

它们不是三套 App，而是三种可以组合的表达层：第一屏用光场表达 Agent，探索页用粒子表达关系，详情页用流体路径表达变化。

光场 Agent 来自 WebGL、Orb、互动光效参考。用于表达“它在听、在想、在回应”，不要变成大按钮。
粒子关系网 来自粒子网站和网络可视化。用于呈现物品、空间、偏好、任务、人之间的上下文强弱。
流体时间轴 来自液体动效和互动叙事。用于展示某个物品一天里的移动、消耗、使用和确认。

参考来源与可借鉴点

这些参考大多不是同类产品。它们帮助我们找到“怎么让界面有生命力”，而不是“怎么排一个记忆列表”。

Awwwards / 互动粒子 可借：WebGL、mousemove、粒子响应。不要借：为了炫技牺牲可用性。 打开参考
Orpetron / 液体动效合集 可借：流动、融合、路径生长。适合对象状态变化和记忆形成过程。 打开参考
Webflow / Particles 可借：粒子、银河、文本粒子、AI particles。适合做“关系场”的轻量视觉。 打开参考
One Page Love / Particles 可借：粒子背景在单页中的克制使用。适合给首页一点生命感，而不是堆组件。 打开参考
Unicorn Studio 可借：可嵌入 WebGL 动效资产的思路。将来真做时可以用类似工具快速验证动效。 打开参考
School of Motion 可借：从 Motion Design 找节奏、转场和情绪，而不是只看 App UI 截图。 打开参考

迁移到 Reality 时的规则

这些视觉机制必须服务记忆中台，而不是服务“看起来很 AI”。所以我建议先定几条约束。

动效必须有语义呼吸表示待机，涟漪表示听取，聚合表示整理，脉冲表示今天有变化。
关系图必须可收敛默认只显示和当前意图有关的 5-9 个节点，不能把所有记忆一次性摊开。
对象位置要稳定即使关系场有生命力，常用入口和关键物品位置也要稳定，帮助用户形成空间记忆。
时间轴要解释变化不是流水账，而是位置、数量、使用、归属、偏好、任务这些状态的变化路径。
