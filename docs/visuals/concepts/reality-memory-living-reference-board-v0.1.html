不要把现实记忆做成物品仓库。它应该像一个会呼吸、会联想、会长出关系的个人现实模型。

这版把外部参考和项目自己的产品文档合在一起：Agent 是有呼吸的存在，物品不是卡片清单，而是和空间、行动、偏好、任务、人际关系相连的上下文节点。

设计结论 第一屏可以非常简单，但它背后要有“生命感”：轻微呼吸、关系流动、重要变化脉冲。物品页不展示商品卡，而展示这个物品和用户一天里的关系、位置、数量、归属、使用和偏好变化。

参考不是抄样式，而是提炼机制。

我把参考分成四类：人格化 Agent、关系网络、空间记忆、现实时间线。Reality 应该从它们各取一部分，但不能像任何一个现有产品。

Dot / New Computer 参考点：个人 AI 不是工具按钮，而是会逐渐理解用户的存在。Reality 可以借这个“长期理解”的表达，但不要走情感陪伴路线。 打开参考
Limitless 参考点：由看见、听见、说过的话驱动的个人 AI 记忆。Reality 的差异是更强调现实物品、空间状态和可删除证据。 打开参考
TheBrain 参考点：知识不必放进文件夹，可以以连接关系存在。Reality 可以借“每件事有多个上下文”，但要避免复杂知识管理工具感。 打开参考
Spatial Memory / NNGroup 参考点：稳定位置帮助用户形成空间记忆。所以关系图可以流动，但关键入口和对象位置不能随便漂移。 打开参考
Voice Assistant Orb 参考点：Agent 可以通过发光、脉冲、涟漪、呼吸表达状态。我们要用克制动效，不做花哨的 3D 球。 打开参考
Map-making Memory Research 参考点：记忆可以绑定到发生的空间，空间不只是物理尺寸，也包含个人经验、价值和优先级。 打开参考

界面语言建议：从卡片转为“场”。

不是不用任何卡片，而是卡片不能成为产品的基本隐喻。Reality 的基本隐喻应该是现实关系场：节点、轨迹、脉冲、分叉、褪色、确认。

Agent 呼吸默认缓慢呼吸；听用户说话时涟漪扩散；整理记忆时有轻微聚合；回答时形成清晰文字。
关系强度线条粗细表达关系强弱；亮度表达新鲜度；虚线表达候选；实线表达确认。
事件脉冲今天发生过变化的节点轻微闪烁，不把所有记忆都推到用户面前。
对象时间轴点击物品后展开一天里的位置、数量、使用者、归属、偏好和任务变化。

可点击关系图小样：点击节点看时间轴。

这里不是最终交互，只是验证“物品不是商品卡，而是上下文节点”的方向。节点可以是物品，也可以是空间、偏好、任务、人。

物品关系位置、容器、常用场景、谁使用过、和哪些任务相关。
